# HyperFrames — Path 2 (Route C): push + parallax swing (warp-proof)

A 3.5s multi-plane parallax push for the **Track-2 oxblood** look. The still is
cut into three depth planes and driven by a virtual camera so the subject reads
as swinging slightly — with **no pixel warping**. The "rotation" is pure
parallax separation between planes.

## Shot spec (as briefed)

| | |
|---|---|
| Canvas | 3840×2160, strict 16:9 |
| Frame rate | 24 fps |
| Duration | 3.5s (84 frames) |
| Register | cinematic photoreal — a lit photographic frame, never stylised/flattened |
| Palette | Track-2 oxblood — near-black `#0B0B0C–#141416`, warm-bone `#EDE8DD`, oxblood-red `#7A160E` (emissive edge glow only), graphite `#3A3A3E` |

## The camera rig (`index.html`)

Three planes sit inside one `#cam` group:

- **Z0 — foreground desk edge** (`assets/z0-desk.png`) — nearest, most parallax.
- **Z1 — subject** (`assets/z1-subject.png`) — mid, near-anchored.
- **Z2 — void + haze** (`assets/z2-void.png` + `.haze`) — furthest, least parallax.

Motion, all on `power3.inOut`, all placed at position 0 so they stay in lockstep:

- **Dolly-in:** `#cam` scales **1.00 → 1.14** (the 14% amplitude), transform-origin
  pinned to the subject's **eye**, so the push converges on the eye.
- **Pan:** ~**8%** of frame width (≈307px) of horizontal swing, split between the
  camera base pan and the differential plane parallax.
- **Parallax shear:** Z0 (near) translates opposite to Z2 (far); the ~0.35·width
  divergence makes the subject appear to rotate slightly. Z1 stays near-anchored.
- **Haze parts toward camera:** the Z2 haze scales up past the lens and thins out.
- **Settle (last 0.6s):** `power3.inOut` decelerates to a dead stop — its tail is
  the settle — while a soft focus bloom fades up on the eye to lock the frame.

### The warp-proof LOCK

Every animated transform is **translateX / translateY / uniform scale only** —
never `rotate`, `skew`, or `matrix`. The base pixels of every plane are never
warped; all apparent rotation comes from planes sliding past one another. The
briefed `CustomEase "power3.inOut"` is served by GSAP's built-in `power3.inOut`
(identical curve, no premium plugin needed).

## ⚠️ The plane art is a STAND-IN

`assets/z0-desk.png`, `assets/z1-subject.png`, `assets/z2-void.png` are
**tonally-correct placeholders** generated by `tools/make_planes.py`. They carry
the correct Z0/Z1/Z2 **depth structure** so the rig can be authored, previewed
and rendered with real plane separation — but they are **not** the final
photographic art, and a graphic stand-in does not satisfy the "cinematic
photoreal" register on its own.

**To finish the shot:** segment the real A-anchor still into the same three
planes at the same 3840×2160 frame and drop them in under the same file names
(subject and desk need alpha/transparency around them; the void is opaque).
Keep the eye near `(33.1%, 21.8%)` of the frame, or update the `transform-origin`
in `index.html` and `EYE` anchors in `tools/make_planes.py` to match.

npm run check     # lint + runtime + layout + motion + contrast
npm run render    # render to MP4 at 3840×2160 @24fps, high quality (silent)
